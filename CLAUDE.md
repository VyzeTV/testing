# Murder Channel: handoff notes for the next agent

A Danganronpa-style killing-game simulation. **The engine decides what happens; a language model only voices it** (dialogue lines, diaries, a few decisions). Python engine in `murder/`, a static browser viewer in `static/`, `server.py` serves both.

## Running and checking

- Tests (mock LLM, no network): `python tests/smoke.py` (1177 checks, about 45 seconds; must end `N/N passed`) and `python tests/baseline.py` (mock calls a day; keep it at or below about 91.7. It is about 91 now, at the ceiling: proposals add about 0.3).
- Balance numbers: `python tests/balance.py --write` (about 30 seconds) writes `docs/BALANCE.md`: deaths and how weeks end, trials and verdicts, sanity, idle time, meals, nights, beliefs and lies caught. Report them at every phase gate. Its 16 weeks give fewer than 20 trials, so verdict counts swing a lot between runs; over 80 extra weeks (seeds 101-140, both configurations) after phase 7 the trial got 75 of 101 verdicts right (74%), 24 wrong, 2 with no verdict. Whole seasons from Day 1 to the ending: `docs/SEASONS.md` (`python tests/season.py --write`, about three minutes; the cast is refilled with newcomers each week as the viewer requires; ways out are reached only rarely). Who kills and who dies per character: `docs/CAST_STATS.md` (`python tests/cast_stats.py --write`, a few minutes; for curiosity only).
- Seed finder and re-voicing (`tests/seed_finder.py`, `murder/revoice.py`): `find --seeds N` ranks mock seasons by how much story they have (wrong or close verdicts, twists, betrayals, NeoVi, affairs; no model calls); `record SEED [--violent] --out DIR` plays one again with `keep_voice` on and writes a save slot (copy it to `state/slots/<name>` and load it in the viewer); `voice DIR --days a-b [--only conv,trial,scene,broadcast]` sends the kept voicing prompts to the real model and writes `DIR_voiced`: same events, speakers and minutes, new words (about a third of a normal day's calls). Uses the user's subscription: ask first.
- Pacing: `python tests/pacing.py` (dead five-minute stretches per block on mock days; meal blocks about 4 of 24 after phase B) and, with a server running, `node tests/pace_check.js` (real seconds per block and how long the map stands still at a block start).
- Browser check: `MC_DATA_DIR=<scratch dir> python server.py &` then `node tests/viewer_check.js` (expects `frozen: 0`, `errors: []`). Use a fresh data dir: a leftover session or an old server on port 8766 gives misleading results. Stop the server with `pkill -f "[s]erver.py"` in its own shell call (an unbracketed pattern kills the shell itself).
- Playwright and Chromium are preinstalled (`/opt/node22/lib/node_modules/playwright`).
- A game must not depend on Python's hash seed: never let set order drive a choice (iterate `sorted(...)` instead). `smoke.py` runs three mock days under `PYTHONHASHSEED=1` and `=2` and fails if they differ, and also fails if two mixins define the same method name.
- Checks that rely on chance (for example "a trial happens in this mock week") should force the outcome (`murder.llm.LLM.mock_murder_prob`, `murders=False`) rather than hope for it.

## How the engine is put together (quick map)

- `engine.py`: `DayRunner` is built from about 45 mixins (one per file).
- `run()` loop: the day's turns at 8..20 in 2-hour steps (`run_tick`), special scenes when due (trial, vigil, last call, presentations, reveal, endgame, finales), then `run_bedtime`, the night blocks (`run_night_block`) and `run_dawn`.
- `run_night()` is a one-tick compatibility version used by tests.
- `emit(tick)` finalises every tick: env, mind, positions, hearing and the deadline hours.
- `run_tick` (phase F1) opens the block (`block_open`, `block_decide` at minute 0), then runs everything else on **one Timeline** (`bk["tl"]`, also `self._block_tl`), each phase at its minute:

  | Minute | What runs |
  |---|---|
  | 0 onwards | Arrivals (`arrival_step` → `arrive_and_act`), each at its own minute |
  | 15 | Passive systems (`block_passive`), then attacks scheduled at the minute attacker and target meet (`block_strikes`; later ones as they come), then free time starts (`block_middle`; slices at 15, 30 ... 105, the meal at its minute) |
  | 20 | Assaults, sabotage, impulses (`block_violence`) |
  | 40 / 90 (free) | Hazards, discovery, the investigation, experiments, TereVi, the rule (`block_world`) |
  | 60 | Dread and drains (`block_drains`) |
  | 56 / 92 (free) | Conversations outside free time and staged ones (`block_talk`; free blocks talk live during the block) |

  At minute 107 `decide_ahead` asks for the next block's decisions early when a viewer watching live has caught up (F4, `ahead.py`, dial `decide_ahead`; `decide_many` uses an early answer if `ahead_sig` is unchanged). Every quarter hour `block_piece` takes in ended conversations and, with a session, hands the viewer the block so far (F5: `on_part`, `sim_partial`, `sess["partial"]`, viewer `playStream`; `?nostream` turns it off; `tests/stream_check.js` with `MC_MOCK_LATENCY` tests it against a slow mock). Positions are forward-only in a day block (F2: `sim_forward`, `Sim.frontier` follows `clock_to`; anything asked for an earlier minute starts at the frontier and is counted in `live["late"]`; NeoVi walks with her chores via `nv_walk`). When the timeline has run out: `block_talk_end` (free-time books closed, voicing, `sim_talk`, `meal_settle`), then `block_close` (reactions, the booth, the inner voice, the director, goals, the proposer). Night blocks still use `free_time` with a timeline of its own.
- **Free time** (`freetime.free_pick`) scores activities from needs and facets.
  - At night only `NIGHT_ACTS` are allowed, plus a `sleep` act.
  - `add(..., far=True)` lets a real need search beyond the normal reach.
- **Method names collide silently across mixins.** Before adding a method, grep for its name; `ConditionMixin.wake_up` (coming round from unconsciousness) was nearly shadowed; `smoke.py` now checks for this.
- **Tuning dials:** `settings.py` (`self.tune(key)`).
- **GM actions:** `session.GM_TYPES` → `story.apply_gm`.
- **Conventions:** comments are sparse and plain; docstrings explain intent. Docs are written in plain, short sentences. Commit messages end with the session's attribution lines.
